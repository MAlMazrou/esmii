## 1. Status definitions

| Status | Meaning | Agent behavior |
|---|---|---|
| `LOCKED` | The user-approved baseline | Implement as written. Do not substitute a preferred technology or pattern without explicit user approval and a recorded update. |
| `DEFAULT` | The approved starting behavior where product input is not required | Use it unless the user changes it before the relevant implementation. Record a change if it affects behavior or architecture. |
| `PROVIDED` | A non-secret user input has been supplied and recorded | Use the recorded value only in the phase that consumes it. It does not authorize external action. |
| `REQUIRED INPUT` | A value or policy only the user can supply | Do not guess. Stop before the listed prompt or feature if unresolved. Never put a credential in this file. |
| `DEFERRED` | Intentionally excluded from the current core | Do not implement. A future trigger is not present authorization. |

When a user changes a decision, keep the decision ID stable, update its status/value/reason, and add a dated note under **Change log**. Do not leave contradictory “old” and “new” active decisions.
